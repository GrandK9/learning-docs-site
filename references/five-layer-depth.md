# 知识点五层深挖（写作规范）

本站单章不能只陈述「项目里做了什么」。每个**独立知识点**（如穿透、Lua 原子块、Cache-Aside）须按下面五层展开；缺任一层视为浅层笔记。

## 五层定义

| 层 | 标题 | 必须回答的问题 | 篇幅指引 |
|----|------|----------------|----------|
| **L1** | 定义与边界 | 是什么、不是什么、在系统中的职责上限 | 2～4 句 |
| **L2** | 动机与失效模式 | 为何需要；若不做/做错，具体会出现什么故障（可量化） | 2～4 句 |
| **L3** | 机制与不变式 | 数据流/状态如何变化；须附 Mermaid（一图一事）+ 官方释义链接 | 1 图 + 段落 |
| **L4** | 方案对比 | 至少 2 种替代方案（业界或官方常见选型）；对比维度表 | 表格 ≥3 行 |
| **L5** | 工程落点与例外 | 项目代码片段、出处、结论；本项目未覆盖或刻意不做的点 | 代码块 + 1 句结论 |

层与层之间用 `### L1 定义与边界` 这类三级标题，便于侧栏 outline 扫读。

## 章节骨架（在章级结构之上）

1. **本章要点**：3～4 条**能力型**陈述（读完后能独立做架构判断，不是目录预告）。
2. **知识点 A/B/…**：每个知识点完整 L1～L5；一章 2～4 个知识点为宜，避免单章过长。
3. **自测**：每题至少跨两层（例如 L2+L4）；答案在 `::: details` 内。
4. **Official links**。

仍保留：**官方释义（意译）** 放在 L3 内或 L3 段首；**禁止**只贴 API 字段表。

## L4 对比表常用维度

按技术类型选取，不必全填：

- 一致性强度（强一致 / 最终一致 / 仅防抖）
- 延迟与吞吐
- 运维复杂度（单点、集群、外部依赖）
- 故障语义（降级、误杀、双写）
- 与本项目约束的匹配度（为何未选）

## 反例（浅层，禁止作为终稿）

> 本项目用 `setIfAbsent` 做锁，防止击穿。

缺 L1 边界、L2 击穿定义与 DB 并发后果、L4 与 singleflight / 永不过期热 key 的对比。

## 正例（L2 片段）

> 热点 key 在过期时刻若 N 个线程同时 miss，回源并发约等于 N；DB 连接池若上限 50，单次击穿即可占满并拖高 P99。互斥锁把回源收敛为 1，其余线程自旋读新值或兜底直查。
